# Наблюдаемость и гигиена секретов

Часть фичи `service-platform` — сначала [`index.md`](index.md).
Две тесно связанные темы: потребитель должен «видеть» статус/живость сервиса из
коробки — **без утечки секретов**. Оба принципа сквозные для всех подсистем
(`KeySource`, транспорты, задания).

## Проверки состояния (health)

| Эндпоинт | Роль | Что показывает |
|----------|------|----------------|
| `/healthz` | liveness | процесс жив |
| `/readyz` | readiness | библиотека загружена **и прошла обязательный самотест** (см. [`../signature-service/native-library.md`](../signature-service/native-library.md)); иначе трафик не принимается |
| `/statusz` | info | версия сервиса/сборки, обнаруженная версия библиотеки, карта возможностей, результат самотеста (`selfTest`) и вердикт совместимости (`compat`), состояние авто-обновления trust-store (`trustRefresh`: вкл/интервал/`lastAt`/число якорей/ошибки), uptime, включённые транспорты, режим (`verify-only`?), backend `JobStore`, размер/загрузка пула воркеров |

**Readiness завязан на самотест**, а не только на «процесс поднялся» — до успешной
загрузки+самотеста Kalkan сервис не принимает трафик. `/statusz` — **без путей к
секретам и чувствительных значений**.

## Метрики (Prometheus `/metrics`)

Число и латентность запросов по операциям и транспортам; ошибки по кодам `KCR_*`;
занятость/сатурация пула воркеров; in-flight и глубина очередей MQ/заданий; статус
самотеста; счётчики «unknown lib version». **Кардинальность лейблов ограничена —
никаких DN/ИИН/серийников в лейблах.**

> **Реализовано** (`internal/metrics`, `prometheus/client_golang`): приватный
> registry, эндпоинт `GET /metrics` (на work-порту рядом с health **и** на отдельном
> `metrics.addr`, который поднимается даже в gRPC/MQ-only-режиме). Метрики:
> `qoltanba_requests_total{transport,op,outcome}` и
> `qoltanba_request_duration_seconds{transport,op}` — пишутся на границе транспортов
> (HTTP-middleware, gRPC-unary-interceptor, MQ-хук в `Processor.Process`; CLI не
> инструментируется — one-shot); `outcome` ∈ `ok|client_error|server_error` (или имя
> gRPC-кода). Внутренние gauge/counter читаются на скрейпе: `qoltanba_pool_workers{state=busy|idle}`
> (загрузка пула Kalkan), `qoltanba_trust_anchors`, `qoltanba_crl_cache_total{result=hit|miss}`,
> плюс стандартные `go_*`/`process_*`. `Recorder` nil-safe (метрики можно не подключать).
> **Ещё не реализовано:** трейсинг (OTel), метрики async-заданий/глубины очередей MQ.

## Логи и трейсинг

- **Логи** (structured, `log/slog`): **уровни** (debug/info/warn/error), формат по
  конфигу — человекочитаемый текст **или опц. JSON** (под сборщики: ELK/Loki).
  Контекст: `correlationId`/`traceId`, операция, коды результата. **Полезная нагрузка
  и любые секреты не логируются** (тела данных — только по явному debug-флагу и без
  секретов).
- **Совместимость с ротацией логов.** По умолчанию пишем в **stdout/stderr**
  (12-factor) — ротацию делает платформа (systemd-journald/docker/`logrotate`); сервис
  файловых дескрипторов не держит. Если включён файловый вывод — **переоткрывать файл
  по `SIGHUP`** (режим `logrotate create`) и не кэшировать fd после ротации, иначе
  логи уходят в удалённый inode; для `copytruncate` — не полагаться на позицию.
- **Аудит-лог** (опционально, отдельно от операционного): субъект, серийник,
  операция, результат, время — **не** ключ/PIN/данные. Обязательность и формат —
  открытый вопрос ([`../../architecture.md`](../../architecture.md)).
- **Трейсинг** (опционально, OpenTelemetry): спаны на операцию, проброс
  `traceparent`/`correlationId` через все транспорты, **включая MQ**.
  - **Почему OTel:** сервис — компонент внутри чужой системы, OTLP вендор-нейтрален →
    наш спан вшивается в *существующий* трейс потребителя независимо от его бэкенда
    (Jaeger/Tempo/Datadog/…). Для open-source с разнородными потребителями это
    правильный lingua franca, а не N вендорных SDK.
  - **Граница (durable):** OTel — для **трейсинга**. **Метрики остаются на Prometheus**
    (pull повсеместен и проще — не навязываем потребителю OTLP-коллектор), **логи — на
    `slog`**(+Sentry). OTLP-экспорт метрик/логов — опциональный мост для стандартизованных
    на OTel, не основной путь. Всё **off by default, fail-open, ноль стоимости без
    сконфигурированного endpoint** (не раздуваем бинарь SDK по умолчанию).
- **Трекинг ошибок** (опционально, Sentry/совместимый): ошибки и паники с контекстом
  (операция, транспорт, код) — **под той же редакцией секретов** (без payload/ПДн/
  ключей). Включается конфигом; недоступность коллектора **не влияет** на работу
  (fail-open, как вся телеметрия).

Вся observability включается/выключается конфигом; порт метрик/health может быть
отделён от рабочего порта.

## Гигиена секретов (сквозное правило)

- **Что считается секретом:** приватный ключ и его байты (PKCS#12), пароли к
  контейнерам, PIN токенов, мастер-пароль встроенного keystore, **содержимое
  подписываемых данных** (потенциально ПДн).
- **Где секреты запрещены:** логи, метрики (значения **и** лейблы), трейсы, тела
  ошибок, ответы-эхо, `/statusz`, дампы конфигурации, отладочный вывод.
- **Меры:** централизованная редакция при сериализации; типы-обёртки (`Secret[T]`)
  с безопасным `String()`/маршалингом; запрет логировать request/response целиком;
  эфемерное хранение ключевого материала и затирание после использования; секреты —
  только из env/файлов-секретов/секрет-менеджеров, не из аргументов CLI и не из репо.
- **Транспорт:** inline-режимы ключей — только по TLS/локальному сокету (см.
  [`keysource.md`](keysource.md)); для сетевых транспортов — рекомендации по
  mTLS/авторизации (точная политика — открытый вопрос).
- **Линт/тесты:** проверки, что структуры логов/ошибок не содержат секретных полей.

## Конфигурация

Единый источник — **defaults + файл + env + флаги**, слоями через **koanf** (не
viper — не раздуваем бинарь; см. границу телеметрии выше). Секреты — **только** через
env/секрет-файлы, никогда флагом.

**Приоритет (низший → высший):** `defaults (код)` < `config-файл` < `env` <
`CLI-флаги`. Отдельной осью — секрет-файлы: `<KEY>_FILE` перекрывает `<KEY>` из env.

**Единый реестр ключей.** Каждый параметр объявляется один раз; из него выводятся все
три имени — флаг `--log-level`, env `QOLTANBA_LOG_LEVEL`, поле YAML `log.level` (префикс
env `QOLTANBA_`, вложенность YAML ↔ env через `_`). Три списка вручную не ведём —
рассинхрон иначе неизбежен. Параметр с `secret: true` **исключается из CLI-флагов** и
маскируется в дампах.

**Формат файла:** YAML основной (знаком ops, K8s-native, комментарии/вложенность);
TOML/JSON читаются тоже (бесплатно с koanf). Env-only-режим (без файла) обязан
работать.

**Секрет-файлы (`<KEY>_FILE`):** значение читается из файла — дружит с Docker/K8s
secrets и systemd `LoadCredential=`. Механика редакции/обёрток `Secret[T]` — в
секции «Гигиена секретов» выше.

**Инструменты оператора:**

- `config dump` — эффективный конфиг с origin каждого значения
  (default/file/env/flag); секреты как `***` (та же редакция, что и `/statusz`).
- `--check-config` (dry-run) — fail-fast валидация на старте, **все** ошибки списком,
  для CI/CD.

**Hot-reload по `SIGHUP` — открытый вопрос** ([`../../architecture.md`](../../architecture.md)):
перечитываем только «дешёвую» подгруппу (log-level, payload-флаги, endpoint'ы
телеметрии); смена `lib-path`/размера пула требует рестарта. Согласовано с
переоткрытием лог-файла по `SIGHUP` выше.

**Группы параметров** (ориентир, актуальный перечень — в реестре app-кода
*(nascent)*, здесь не дублируем): библиотека (`lib-path`/`lib-version`/`lib-compat`/
`lib-min-version`/`ca-certs-dir`), воркеры (`workers`), транспорты (`http`/`socket`/`grpc`/
`amqp-url`/`kafka-brokers`/`nats-url` — включаются по мере задания), ключи
(`keystore-mode`, `builtin-keystore-dir`; см. [`keysource.md`](keysource.md)), режим
(`verify-only` — отключает ключевой путь и `sign`-эндпоинты, см. [`index.md`](index.md)),
задания (`job-store=memory|bbolt`, `job-store-path`), наблюдаемость (`metrics`/
`log-level`/`log-format`/`otel-endpoint`/`log-payloads=false`).
