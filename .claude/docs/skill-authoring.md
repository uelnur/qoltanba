# Написание скиллов — Progressive Disclosure

Читать перед созданием или изменением любого скилла в `.claude/skills/<name>/`. Скиллы обязаны следовать Progressive Disclosure (PD): читатель загружает только то, что нужно текущей задаче.

## Ось разбиения

Разбивай по **«нужно всегда» vs «нужно иногда»**, никогда по теме. Разбиение, где каждая часть срабатывает на одной и той же задаче, — это просто монолит, размазанный по файлам, хуже, чем один файл.

Две валидные формы (выбирай по домену или комбинируй):

- **Маршрутизация** — у домена есть взаимоисключающие варианты задач (напр. тип тестового набора). `SKILL.md` маршрутизирует ровно к одному ref; задача читает один.
- **Общий путь + edge-ref-ы** — иначе. `SKILL.md` самодостаточен для типичной задачи (общий случай открывает ноль ref-ов); ref-ы держат только условный/редкий материал и отдельные суб-артефакты.

## SKILL.md

- Frontmatter: `name`, `description` (триггер — конкретный, с примерами; так скилл обнаруживается), `version` (поднимать при изменении).
- Коротко: интро → универсальные правила/конвенции → таблица маршрутизации → финальный гейт (команды lint/test, чеклист).
- Таблица маршрутизации: жирные имена файлов `**ref-x.md**`, каждый с одной строкой «читать, когда…», плюс «читай тот, что для твоей задачи».
- ОБЯЗАТЕЛЬНЫЙ скилл также получает строку в таблице «Скиллы — ОБЯЗАТЕЛЬНЫЕ» в `CLAUDE.md`.

## ref-*.md

- Без frontmatter. Открывай `# Заголовком` + одним предложением: что покрывает + «Часть скилла `<skill>` — сначала прочитай SKILL.md».
- Самодостаточный how-to по одной условной под-теме.

## При реструктуризации

Переноси контент дословно — PD перемещает, а не суммирует и не выбрасывает. Удаляй устаревшие ref-ы; держи каждый указатель на `ref-*.md` разрешимым.
