# Стиль кода: язык, комментарии, имена

Правила оформления **кода** (Go/C). Читать перед тем, как писать или править код.
Проектные доки (`.claude/docs/`) ведём на русском — это рабочий язык команды; **код
— на английском**. Обоснование: проект открытый, код читают и форкают вне КЗ;
идентификаторы Go и так английские, смешение с русскими комментариями выглядит
рвано; строки ошибок библиотеки/сервиса встраивают в чужие системы — по-английски
они гуглятся и совпадают с конвенцией Go.

## Инженерное качество (production-ready по умолчанию)

Пишем как сеньор: код, который не роняет процесс, деградирует предсказуемо и читается
без автора. Это не опция «на потом» — это база для каждого изменения.

- **KISS вперёд, SOLID/DRY — в помощь читаемости, не ради слоёв.** Явное лучше
  «магии». Не абстрагируй до второго реального потребителя — **дублирование дешевле
  неправильной абстракции**. SOLID применяем там, где он изолирует изменение, а не для
  симметрии. Оверинжиниринг — такой же дефект, как копипаста.
- **Low coupling / high cohesion — через порты (уже архитектурно).** Зависимости
  направлены внутрь; домен не знает про cgo/транспорт; связь между слоями — только
  через объявленные потребителем интерфейсы; пакет = одна связная ответственность
  (правила и границы — [`architecture.md`](architecture.md)).
- **Рантайм-устойчивость — «не падать».** Учитывать нюансы рантайма, а не только
  happy-path:
  - **Паника не убивает процесс:** `recover` на границах воркера/транспорта/порождённых
    горутин → преобразование в ошибку. Паника ≠ поток управления.
  - **Ни утечек, ни висячих:** каждый ресурс закрывается (`defer`, cleanup при сбое и
    отмене), нет утечек fd/памяти/горутин; уважать `context` (отмена/таймаут);
    **graceful shutdown** дренирует пул воркеров/задания, не рвёт in-flight.
  - **cgo-границы особенно опасны:** мусорный буфер/неверная длина = SIGSEGV — валидируй
    длины (gotcha Kalkan — см. комментарии и [`kalkan-api/`](kalkan-api/index.md)).
- **Опциональные зависимости деградируют, а не валят старт.** Observability (Prometheus/
  Sentry), TSA, внешний job-store — отключаемы; их отсутствие/сбой не роняет сервис:
  **fail-open для телеметрии**, **fail-closed для крипты/безопасности**.
- **Observability и логи — часть кода, а не post-hoc.** Durable-правила (уровни, опц.
  JSON, опц. Prometheus/Sentry, совместимость с ротацией, гигиена секретов) —
  [`features/service-platform/observability-security.md`](features/service-platform/observability-security.md).

## Язык

- **Английский** — все комментарии, идентификаторы (пакеты, типы, функции, поля,
  переменные, файлы) и **тексты сообщений** в коде: ошибки, логи, сообщения
  тестов, диагностика.
- **Русский** — только `.claude/docs/` и прочая командная документация. В коде
  русского текста быть не должно (исключение — доменные литералы данных, напр.
  тестовые строки с казахскими/русскими символами по существу задачи).

## Ошибки и сообщения

- Возвращаемые/оборачиваемые ошибки — по конвенции Go: со строчной буквы, без
  завершающей точки, кратко. Префикс пакета сохраняем (`kalkan: …`, `provider: …`).
- Логи и сообщения тестов (`t.Fatalf`/`t.Logf`/`Fprintln`) — обычные английские
  фразы, кратко.
- Нативные коды `KCR_*` наружу не текут: драйвер маппит их в типизированные
  ошибки `provider`.

## Комментарии — что оставлять, что убирать

Оставляем **только то, что трудно извлечь из самого кода**:

- **Почему** так сделано (обоснование, компромисс, неочевидное решение).
- Неочевидные инварианты и тонкости конкурентности/памяти/безопасности.
- Особенности нативной либы (gotcha Kalkan: коды, флаги, «длина-потом-данные»,
  риск SIGSEGV на мусорном буфере).

Убираем:

- Комментарии, **пересказывающие код** («увеличиваем счётчик», «возвращаем res»).
- **Транзиентные/строительные** заметки — отсылки к процессу исследования,
  временному состоянию, «как в probe/пробнике», «пока/сейчас/временно».
- **Ссылки на `.claude/docs`** и прочие командные доки из кода. Нужную суть
  формулируем инлайн; долгоживущее знание фиксируем в доке, а не ссылкой из кода.

Doc-комментарий экспортированного идентификатора начинается с его имени (конвенция
Go): `// Provider is …`.

## Имена

Имена — самоописательные: по типу/функции/переменной/файлу понятно назначение без
чтения тела. Избегаем аббревиатур, не принятых в домене, и «умных» сокращений.
Аббревиатуры домена КЗ ЭЦП оставляем как есть (IIN/BIN/OCSP/CRL/CMS/WSSE/…).
